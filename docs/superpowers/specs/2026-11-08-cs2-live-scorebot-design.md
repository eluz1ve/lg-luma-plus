# CS2 live: скорборд и game log в карточке матча

Дата: 2026-11-08. Репозитории: `eluz1ve/lg-luma` (ветка `integration`) и `eluz1ve/luma-feeds`.

## Зачем

Сейчас карточка CS2 в Luma+ показывает live-матч по данным Liquipedia, а там нет счёта по
раундам, пока карта не закончится. На HLTV в это время идёт скорборд, лента событий и история
раундов. Хочется видеть то же на телевизоре: счёт по раундам на главной и полный live в карточке
матча. Плюс одним нажатием открывать стрим матча в приложении Twitch/YouTube/Kick на самом ТВ.

Источник live-данных — скорбот HLTV (socket.io, неофициальный). Его читает только наш сервер,
телевизор ходит только на `luma.eluzive.dev`. Пользователь принял риск неофициального API.

## Цели

1. На главной у live-матчей виден текущий счёт по раундам идущей карты, обновление раз в минуту
   (как сейчас обновляется виджет).
2. В карточке live-матча — скорборд, история раундов и game log, обновление каждые 1–2 с, пока
   карточка открыта. Задержка 2–3 с от HLTV — норма, быстрее не нужно.
3. Строка стримов под заголовком карточки, сортировка по зрителям; OK открывает стрим в
   приложении на ТВ.
4. Сервер держит подключения к скорботу только для матчей, которые идут сейчас.

## Не цели

- 2D-радар, позиции игроков, повторы, демки.
- Live для других игр (Valorant, Dota и т.д.).
- Статистика завершённых матчей с HLTV (итоги остаются из Liquipedia).
- Скорость быстрее 2–3 с, push на ТВ (WebSocket/SSE).

## Анти-цели (провал, даже если «работает»)

- Телевизор ходит на hltv.org напрямую.
- Новый сервис ломает или заметно грузит соседние сайты на сервере (bottlebeer.md,
  eu.take-vpn.com, youtube.linked.ovh) или сам Caddy.
- Карточка не live-матча или live-матча без данных HLTV выглядит хуже, чем сейчас.
- Любые запросы к Liquipedia, кроме вики `counterstrike` (договорённость с Liquipedia).
- IP сервера в публичном репозитории.

## Экран: карточка live-матча

Макет согласован в брейншторме (`live-card-v5.html`, плюс правки из чата ниже). Логическое
разрешение 1920×1080, карточка той же ширины, что сейчас (≈1328 px), без прокрутки.

Сверху вниз:

1. **Заголовок.** Лого турнира, название. Подзаголовок одной строкой: `Counter-Strike 2 · <stage> ·
   <Opening/Decider/…> · BO<n> · Tier <n> · Онлайн/LAN`. Отдельных плашек BO3/Tier больше нет.
2. **Стримы.** Одна строка чипов: иконка платформы, канал, язык. Сортировка по зрителям (убывание).
   Чип показывается только если соответствующее приложение установлено на ТВ. Нет ни одного —
   строки нет. OK на чипе запускает приложение с конкретной ссылкой.
3. **Шапка** (один блок): команды слева/справа, в центре счёт серии и LIVE. Под ними в том же
   блоке — тайлы карт: сыгранные с итоговым счётом, идущая подсвечена, со счётом по раундам в
   цветах сторон (CT синий, T жёлтый) и номером раунда.
4. **Низ, две колонки:**
   - Слева (~60% ширины) — скорборд в стиле HLTV: строка `R: <раунд> · <карта>`, счёт, статус
     раунда; полоса команды в цвете её текущей стороны; пять строк игроков на команду; между
     командами — история раундов иконками (тип победы: устранение, взрыв, разминирование, время;
     разделитель половин). Колонки: ник, HP (полоска), $, Op. duels (entry K:D), KAST, K (hs), A,
     D, ADR. Погибшие в раунде приглушены.
   - Справа — game log: плашки событий, свежие сверху. Убийство: убийца(+ассистент) в цвете
     стороны, иконка оружия, иконки модификаторов (хедшот, через смок, прострел — если есть в
     данных), жертва. «Round over · Winner: CT (12 - 10) · Enemy eliminated» и «Round started»
     — тем же мелким шрифтом, что друг у друга, мельче строк убийств; «Round over» переносится
     на вторую строку, если не влезает. Плюс бомба заложена/разминирована.
5. **Подвал** как сейчас; источник: `Live: HLTV · карты: Liquipedia`.

Если live-данных нет (сервис не нашёл матч на HLTV, файл старше 30 с, ошибка сети) — карточка
выглядит как сейчас (составы, карты из Liquipedia), без пустых панелей.

Иконки game log и истории раундов — SVG из CS2 (killfeed/equipment Valve). Решение пользователя:
кладём их в публичный форк в `assets/` (с пометкой об источнике, как у других SVG), компилируются
в `.lvec` как остальные иконки. Оружие, которого нет в наборе, рисуется текстом.

## Данные: сервер (luma-feeds)

### Сервис `cs2-live`

Долгоживущий процесс на сервере фидов рядом с `/opt/LumaFeeds` (systemd unit), Node.js. Основа —
форк `cybersamuurai/HLTV` (форк `gigobyte/HLTV`, есть `connectToScorebot` и обход Cloudflare через
Puppeteer). Как подключить (свой форк в `eluz1ve`, vendor в luma-feeds, npm с git-ссылкой) —
на усмотрение исполнителя; пользователь назвал этот форк «который надо допилить».

Цикл:

1. Читает `www/cs2/matches.json` (его по-прежнему пишет `run.sh` из Liquipedia).
2. Для каждого матча `state: live` находит id матча на HLTV: список текущих матчей HLTV,
   сопоставление по названиям команд (нормализованным) и времени начала. Найденную пару
   `liquipedia id → hltv id` запоминает.
3. Открывает подключение к скорботу (`readyForMatch`), подписка на `scoreboard` и `log`.
   Матч перестал быть live в `matches.json` или скорбот сообщил конец — подключение закрыть.
4. Раз в секунду, если что-то поменялось, атомарно (tmp + rename) пишет
   `www/cs2/live/<liquipedia id>.json`. Раз в ~30 с — `www/cs2/live/index.json` для главной.
5. Со страницы матча HLTV берёт стримы (платформа, канал/ссылка, язык, зрители) — раз в
   несколько минут.

Caddy уже раздаёт `www/`; для `cs2/live/*` нужен `Cache-Control: no-store` (или очень короткий),
чтобы Cloudflare и сам ТВ не держали старое. Правка Caddyfile — по процедуре из памяти: diff
`caddy adapt`, `Caddyfile.bak-<epoch>`, `caddy validate`, `systemctl reload caddy`, проверка
соседей.

### Формат `cs2/live/<id>.json` (черновик, исполнитель может уточнить)

```json
{
  "id": "<liquipedia id>",
  "hltv": 2400227,
  "updated": 1794160563,
  "map": "Mirage",
  "round": 24,
  "score": {"ct": 10, "t": 13},
  "sides": {"ct": 0, "t": 1},
  "frozen": false,
  "bomb_planted": false,
  "players": [[{"nick": "snowiee", "alive": true, "hp": 100, "money": 4150, "kills": 18,
                "hs": 10, "assists": 3, "deaths": 16, "adr": 79.9, "kast": 60.9,
                "entry": [0, 2], "weapon": "m4a1_silencer"}], [...]],
  "history": [{"round": 1, "winner": 1, "type": "elimination"}],
  "log": [{"type": "kill", "killer": "jERK0z", "killer_side": "ct", "assister": null,
           "victim": "Slexa", "victim_side": "t", "weapon": "m4a1_silencer",
           "headshot": true, "smoke": false, "wallbang": false},
          {"type": "round_end", "winner": "ct", "ct": 12, "t": 10, "reason": "elimination"},
          {"type": "round_start"}],
  "streams": [{"platform": "twitch", "channel": "cct_cs2", "url": "...", "language": "en",
               "viewers": 4120}]
}
```

`players[i]` — по порядку команд в `matches.json`. `log` — последние ~40 событий текущей карты.
`index.json` — `{"updated", "matches": {"<id>": {"map", "round", "score": [a, b]}}}` в порядке
команд Liquipedia.

## Данные: телевизор (lg-luma)

- Главная: раз в минуту, как сейчас, вместе с `matches.json` читает `cs2/live/index.json` и
  показывает счёт по раундам идущей карты. **Решение пользователя: во всех трёх местах** —
  строка матча в виджете CS2 (`cs2_row`), тайл идущей карты на карточке Home
  (`cs2_card_maps`, сейчас там «LIVE») и строки live-матчей в «Сегодня». Нет файла — как сейчас.
- Карточка: пока она открыта и матч live, каждые 2 с читает `cs2/live/<id>.json` с того же
  домена (запасного GitHub Pages для live нет). HTTP — вне SDL-потока, как остальные запросы;
  ограничение размера ответа, таймауты, без редиректов.
- Стримы: проверка установленных приложений по инвентарю, который у Luma уже есть.
  YouTube `youtube.leanback.v4`, Twitch `tv.twitch.tv.starshot.lg`; id Kick — найти на ТВ.
  Запуск — `luna://com.webos.applicationManager/launch` с `params`. YouTube: прямая ссылка на
  эфир (с HLTV она уже на видео) через `contentTarget`. Twitch/Kick: ссылка на канал, приложение
  само открывает эфир. Точные `params` для Twitch и Kick и id приложения Kick **подбирает
  исполнитель сам на ТВ** через ares (`lgtv`) пробными запусками (решение пользователя). Kick на
  ТВ не установлен — его чипы не показываются, id выяснить по магазину LG или отложить.

## Ограничения

- Сервер общий; Chromium для Puppeteer — только для получения страниц HLTV, не держать открытым
  постоянно; лимит памяти в systemd unit.
- Liquipedia: только `counterstrike`, сервис `cs2-live` к Liquipedia не обращается вовсе.
- Тесты не ходят в сеть (ни HLTV, ни ТВ). Длинные прогоны (smoke/полные) не запускать —
  сборка, установка на ТВ, пользователь проверяет сам.
- Коммиты — только от eluz1ve, без Co-Authored-By. Перед пушем в main показать результат и текст
  коммита. Работа форка — в `integration`.
- Изменения поведения — с changeset.

## Решено пользователем

- Live берём с HLTV через сервер, ТВ к HLTV не ходит.
- Главная раз в минуту, карточка — реальное время; 2–3 с задержки достаточно.
- Раскладка карточки как выше (макет v5 + правки).
- Стримы: сортировка по зрителям; YouTube — прямая ссылка на эфир, Twitch/Kick — на канал;
  нет приложения — прячем.
- SVG-иконки Valve — в публичный форк.

## Уточнения после ревью

- **Колонки скорборда.** Скорбот отдаёт их сам (по типам форка `cybersamuurai/HLTV`,
  `ScoreboardPlayer`): `hp`, `money`, `score`/`assists`/`deaths`, `damagePrRound` (ADR),
  `advancedStats.kast`, `entryKills`/`entryDeaths` (Op. duels), `alive`, `primaryWeapon`.
  Считать из лога ничего не нужно. Хедшотов в скорборде нет: `K (hs)` — hs считаем из `log`
  (Kill.headShot) с момента подключения; при подключении посреди карты hs может быть неполным —
  тогда показываем только K. (Решение Claude.)
- **Первый шаг — разведка на сервере (решение Claude).** До всего остального: на сервере фидов
  подключиться к одному идущему матчу через форк и записать сырые `scoreboard`/`log` (заодно
  станет видно, есть ли флаги смока/прострела). HLTV не пускает сервер (Cloudflare по IP
  датацентра, обход Puppeteer не работает) — **решение пользователя: пробуем через прокси**
  (HTTP/SOCKS для запросов страниц и для socket.io; адрес и доступ — в `feeds.env`, не в репо).
  Не помогает и прокси — остановиться и вернуться к пользователю.
- **Сервер (проверено 2026-11-08):** 4 CPU, 7.9 ГБ RAM, доступно ≈2.4 ГБ, swap нет, Node 24 есть
  (nvm и /usr/bin/nodejs), Chromium нет. Chromium ставится только для Puppeteer, запускается по
  требованию и закрывается; `MemoryMax` в unit. SSH с этого Mac есть. (Решение Claude.)
- **Деплой сервиса (решение Claude).** Код в `luma-feeds/live/`, `server/install.sh` ставит
  зависимости и systemd unit; обновление — отдельная команда (git pull + `npm ci` +
  `systemctl restart`), не через `run.sh`.
- **Когда подключаться (решение Claude).** «live» в `matches.json` — по расписанию и может отставать
  до 15 мин. Сервис сверяется ещё и со списком live-матчей HLTV: подключается, когда матч live на
  HLTV и есть в `matches.json` (live или upcoming в ближайший час); отключается, когда HLTV
  перестал считать его live. id в файлах — всегда Liquipedia.

## На усмотрение исполнителя

- Как подключить форк HLTV, язык обвязки сервиса (Node обязателен из-за библиотеки).
- Точный формат JSON, частота записи `index.json`, глубина log.
- Алгоритм сопоставления матчей Liquipedia ↔ HLTV.
- Есть ли в сырых событиях флаги «через смок»/«прострел»; нет — эти иконки не рисуем.
- Мелкие детали вёрстки в рамках макета.
